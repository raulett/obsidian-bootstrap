# Softmus Second Brain - стартовый шаблон

Преднастроенное хранилище [Obsidian](https://obsidian.md) для ведения личной базы знаний (*second brain*) с поддержкой работы AI-агента. Вместо "голого" Obsidian вы сразу получаете рабочую структуру папок, набор плагинов, единые конвенции ссылок и дат, синхронизацию через Git и готовые инструкции для AI - из коробки в формате Claude Code, но шаблон не привязан к конкретному харнесу (годится и Codex).

База знаний управляется **в две руки**: вы - через интерфейс Obsidian, AI-агент - через файловую систему.

Он рассчитан на тех, кто хочет быстро начать работать в Obsidian, не настраивая его с нуля. Это **рекомендация, а не жёсткая схема**: любую папку, файл или настройку можно изменить или убрать под себя. Смотрите рекомендации ниже.

## TL;DR - что внутри

- **Структура папок** под методику second brain: входящие, база знаний, встречи, проекты, архив.
- **Несколько community-плагинов** + донастроенные core-плагины (Bases, Canvas, Templates). Минимальные базовые удобства, которых нет в коробочной версии.
- **Единые конвенции:** Markdown-ссылки с абсолютным путём, вложения в `_files/`, автоведение дат во frontmatter.
- **Git-синхронизация** через плагин (pull при старте + авто-commit/pull/push каждые 15 минут).
- **Готовность к AI:** инструкции `CLAUDE.md` и скиллы в `.claude/skills/` - из коробки под Claude Code, переносится и под Codex.

## Установка

### Шаг 1. Установите Obsidian

Скачайте и установите Obsidian для своей ОС с [obsidian.md/download](https://obsidian.md/download).

### Шаг 2. Получите шаблон (без git-истории)

Шаблон лежит в `git.softmus.ru/Softmus/Obsidian-bootstrap`. Вам нужна **рабочая копия без истории** репозитория-шаблона - дальше вы ведёте её в **своём личном** репозитории.

**Вариант А - скачать архивом (проще):**

1. Откройте репозиторий шаблона в веб-интерфейсе.
2. Скачайте архив [Download ZIP](https://git.softmus.ru/Softmus/Obsidian-bootstrap/archive/main.zip).
3. Распакуйте в папку будущего хранилища, например `~/Softmus-Obsidian`.

**Вариант Б - через git с удалением истории:**

```bash
# 1. Поверхностный клон (только последний коммит)
git clone --depth=1 https://git.softmus.ru/Softmus/Obsidian-bootstrap.git ~/Softmus-Obsidian
cd ~/Softmus-Obsidian

# 2. Отвязать от шаблона - удалить его историю
rm -rf .git          # Windows (PowerShell): Remove-Item -Recurse -Force .git

# 3. Начать свою историю и подключить ЛИЧНЫЙ репозиторий
git init
git branch -M main
git remote add origin <URL-вашего-личного-репозитория>
git add .
git commit -m "init: second brain from bootstrap"
git push -u origin main
```

> Подключайте **свой** репозиторий, а не шаблонный: `origin` должен указывать на **ваш личный** репозиторий, иначе вы рискуете запушить личные заметки в общий шаблон. Личный репозиторий заранее создайте пустым в `git.softmus.ru` (или там, где вам удобно).

### Шаг 3. Откройте папку как хранилище

В Obsidian: **Open folder as vault** → выберите папку из шага 2.

При первом открытии Obsidian спросит про сторонние плагины - нажмите **Trust author and enable plugins** (выход из Restricted Mode). Плагины уже перечислены в шаблоне и включатся автоматически - кроме **Git**: он намеренно оставлен выключенным, чтобы не синхронизировать хранилище до того, как вы подключите свой репозиторий. Его вы включите вручную на шаге 4.

После первого запуска проверьте обновления и убедитесь, что плагины включены: **Settings → Community plugins** → **Check for updates** (при наличии - **Update all**), затем пробегитесь по списку и включите те, что остались выключенными.

### Шаг 4. Проверьте синхронизацию

После настройки git (шаг 2) и первого запуска **убедитесь, что плагин Git включён**: **Settings → Community plugins** → найдите **Git** и включите его, если он выключен. Без включённого плагина автоматическая синхронизация файлов работать не будет.

Плагин **Git** настроен на автоматическую синхронизацию: `pull` при старте (`autoPullOnBoot`), плюс авто-commit-and-sync и авто-`pull` каждые 15 минут (коммит происходит через 15 минут после последней правки). Меняйте заметки, ничего не нажимая, - изменения сами уедут в ваш репозиторий. Синхронизировать немедленно: палитра команд → `Git: Commit-and-sync`.

> Возможны merge-конфликты
> При расхождении истории (например, правки с двух устройств или чужой push) плагин выдаст merge-конфликт и **не разрешит его сам** - это придётся сделать вручную через git-клиент. Если работаете с нескольких устройств, открывайте Obsidian по очереди и дожидайтесь синхронизации.

### Шаг 5 (опционально). Настройте AI-агента

См. раздел [Работа с AI-агентом](<#работа-с-ai-агентом>) - там установка CLI и обзор скиллов.

## Обновления и автономность копии

Централизованного обновления шаблона **не предусмотрено и не планируется**. Как только вы развернули копию (шаг 2), она становится **изолированной**: дальше вы сами распоряжаетесь настройками, своими записями, структурой хранения и набором расширений - подстраивайте всё под себя.

В каждой папке шаблона лежит короткий `README.md` с описанием её назначения, а в корне - файл `theme-preview.md` со всеми элементами разметки для проверки оформления тем. Это вспомогательные файлы: их можно спокойно удалить, переименовать или перестроить всю структуру директорий под себя.

Если в шаблоне появилось обновление, которое вам интересно, накатывать его вручную не нужно - просто попросите AI-агента перенести нужные изменения в вашу копию.

При всей свободе ради сохранности данных и совместимости рекомендуется придерживаться трёх вещей:

- **Бэкапьте всё в персональный git компании** - это и так делает плагин Git (см. шаг 4), не отключайте его.
- **Не меняйте формат ссылок** (Markdown + абсолютный путь от корня) - иначе ломается совместимость с git-инструментами и AI.
- **Оставьте включённым плагин автоведения дат** (Frontmatter Date Manager) - на нём держатся поля `created` / `updated`.

## Как пользоваться (метод second brain)

База - это не свалка файлов, а растущий граф связанных заметок. Рабочий цикл:

1. **Захват.** Всё новое и недодуманное - в `inbox/`. Не раскладывайте преждевременно.
2. **Разбор inbox.** Периодически разбирайте входящие: дробите на атомарные заметки, добавляйте ссылки на связанное, переносите "вечнозелёное" в `knowledge/`, встречи - в `meetings/`, проектное - в `projects/`.
3. **Связывайте.** Стройте граф Markdown-ссылками между заметками - связи ценнее тегов и папок.
4. **Архивируйте, не удаляйте.** Потерявшее актуальность переносите в `archive/`.
5. **Ресёрч.** Изучая тему, собирайте источники и сохраняйте готовую заметку в `inbox/`.

### Структура папок

| Папка        | Назначение                                                             |
|--------------|------------------------------------------------------------------------|
| `inbox/`     | Входящие: быстрый захват, неразобранные черновики, результаты ресёрча. |
| `knowledge/` | Постоянная база знаний: атомарные "вечнозелёные" заметки.              |
| `meetings/`  | Заметки встреч.                                                        |
| `projects/`  | Проектные заметки и материалы.                                         |
| `archive/`   | Устаревшее - не удаляем, а архивируем.                                 |
| `_files/`    | Вложения (картинки, PDF). Скрыта из навигатора.                        |
| `templates/` | Шаблоны заметок.                                                       |

## Чем шаблон отличается от коробочного Obsidian

Все отличия подчинены одной задаче: база должна оставаться связной и переносимой - одинаково удобной и вам в интерфейсе, и AI-агенту через файлы.

**Ссылки и раскладка.** Внутренние ссылки - обычные Markdown-ссылки с абсолютным путём от корня, а не wikilinks, как в Obsidian по умолчанию. Они читаются как простой текст и вне Obsidian, не засоряют git-диффы и понятны AI-агенту, а при перемещении и переименовании заметок ссылки вместе с вложениями автоматически остаются в порядке. Новые заметки сразу создаются в `inbox/` - единой точке захвата, не нужно каждый раз выбирать папку; вложения уходят в скрытую `_files/` и не зашумляют дерево; удалённое отправляется не в системную корзину, а в локальную внутри хранилища - так его проще вернуть.

**Внешний вид.** Вместо дефолтной темы - Tokyo Night с фирменным акцентом и лёгкой прозрачностью, единый узнаваемый вид из коробки. Ограничение читаемой ширины строки снято, поэтому под широкие таблицы и представления Bases остаётся всё окно.

**Что включено в ядре.** Из встроенных модулей активно ровно то, что нужно базе знаний: Bases (табличные и карточные представления `.base`), Canvas, шаблоны, свойства, оглавление и закладки. Всё лишнее - ежедневные заметки, веб-вьюер, слайды, диктофон и прочее - выключено, чтобы не отвлекать; платные Publish и Sync тоже, их роль берёт на себя Git.

**Плагины-помощники.** Поверх ядра - дюжина community-плагинов, закрывающих то, чего в коробке нет: удобный файловый навигатор, мгновенный полнотекстовый поиск, автоведение дат во frontmatter, работа с Markdown-таблицами, автоформатирование заметок при сохранении. Отдельно стоит синхронизация: плагин Git настроен забирать и отправлять изменения сам, так что заметки уезжают в ваш репозиторий без ручных коммитов, а Local REST API даёт AI-агенту канал для поиска по базе. Полный список - ниже.

## Работа с AI-агентом

Шаблон рассчитан на то, что часть рутины ведёт AI-агент: захват, структурирование, связывание и поиск по базе. Канонические конвенции хранилища и инструкции для агента лежат в [`CLAUDE.md`](</CLAUDE.md>). Из коробки шаблон заточен под **Claude Code** - он подхватывает файл автоматически из корня, - но харнес не зашит жёстко: ниже описаны три варианта - Claude Code, Codex и Claude Desktop.

### Claude Code (из коробки)

**Claude Code** - официальный CLI Anthropic. Установите по инструкции [docs.claude.com/claude-code](https://docs.claude.com/en/docs/claude-code). Он автоматически подхватывает `CLAUDE.md` и скиллы из `.claude/skills/`.

Запускайте CLI из корня хранилища - тогда агент видит инструкции и работает по конвенциям базы.

### Codex (через миграцию)

Если вы работаете в **Codex CLI** (агентский CLI от OpenAI), переносить файлы вручную не обязательно - попросите сделать это сам Codex.

Ключевая разница: Codex по умолчанию читает не `CLAUDE.md`, а `AGENTS.md`, а скиллы ищет в `.agents/skills/`, а не в `.claude/skills/`. Формат `SKILL.md` - открытый стандарт, который понимают и Claude Code, и Codex, так что сами скиллы переносятся почти без изменений.

У Codex есть официальный скилл `migrate-to-codex` именно для такого переноса: он сканирует `.claude/` (инструкции, скиллы, MCP-конфиг) и пишет результат в нативные форматы Codex, не трогая исходные файлы Claude Code - откатиться можно в любой момент. Откройте корень хранилища в Codex и дайте такой промпт:

```
Установи и запусти официальный скилл Codex migrate-to-codex ($skill-installer migrate-to-codex),
чтобы перенести конфигурацию Claude Code этого репозитория - CLAUDE.md, CLAUDE.local.md,
.claude/skills/ и .mcp.json (.mcp.json.template) - в нативные форматы Codex: AGENTS.md, .agents/skills/
и .codex/config.toml. Исходные файлы Claude Code не трогай - хочу сохранить
возможность вернуться к нему в будущем. Доведи миграцию до конца сам:
scan → dry-run → запуск → правка блоков "MANUAL MIGRATION REQUIRED" → validate,
не останавливаясь на промежуточных шагах. В конце покажи отчёт - что перенесено
автоматически, что требует ручной проверки и что не имеет аналога в Codex.
```

После миграции пробегитесь по отчёту: конвенции из `CLAUDE.md` должны без потерь смысла перейти в `AGENTS.md`, а MCP-серверы из `.mcp.json` - в `.codex/config.toml`.

### Claude Desktop (режим Code)

Claude Desktop (GUI-приложение) - не только чат. У приложения три режима (табы вверху окна): **Chat**, **Cowork** и **Code**. Для работы с хранилищем используйте таб **Code** - это тот же Claude Code, что и в терминале, только с графическим интерфейсом.

### Как агент пишет в базу

Агент читает и пишет `.md` напрямую через файловые инструменты - проще, быстрее, работает и при закрытом Obsidian. Запущенный Obsidian мгновенно подхватывает изменения на диске, поэтому агент сверяется с актуальным состоянием файла перед правкой.

Для **поиска** по базе агент использует MCP-сервер `obsidian` (omnisearch - релевантный полнотекстовый поиск, точнее grep). Сервер отвечает, только пока Obsidian открыт; при закрытом - поиск идёт через файловые инструменты. MCP здесь - дополнение к файловому доступу, а не замена: запись в базу по-прежнему идёт файлами. Как поднять MCP-серверы (и подключить внешние, например Nextcloud) - в следующем разделе.

### MCP-серверы: настройка

MCP-серверы - дополнительный канал агента поверх файлов: релевантный поиск по базе и внешние интеграции. Их список задаётся в `.mcp.json`.

> **Кажется сложным?** Не настраивайте вручную - откройте хранилище через AI и попросите: "настрой MCP-серверы по инструкции из README". Агент сам скопирует `.mcp.json.template`, задаст недостающие креды Nextcloud и пропишет их, задаст вам вопросы.

**`.mcp.json` не версионируется** (в нём бывают личные креды), поэтому в шаблоне он поставляется заготовкой **`.mcp.json.template`**. Скопируйте её - без этого шага MCP-серверы не поднимутся:

```bash
cp .mcp.json.template .mcp.json
```

После копирования перезапустите Claude Code / Codex. В шаблоне предустановлены два сервера:

- **`obsidian`** - релевантный поиск по базе (omnisearch) через плагин Local REST API. Работает из коробки: адрес и ключ уже прописаны (localhost), менять ничего не нужно.
- **`nextcloud`** - доступ к вашему [Nextcloud](https://home.softmus.ru) (заметки, файлы, календарь, задачи, контакты и др.) через [cbcoutinho/nextcloud-mcp-server](https://github.com/cbcoutinho/nextcloud-mcp-server). До настройки стоит с плейсхолдерами и базе не мешает.

**Подключение Nextcloud.** Понадобятся адрес инстанса, логин и **app-password** (в Nextcloud: **Settings → Security → Devices & sessions**, не основной пароль), а также установленный [`uv`](https://docs.astral.sh/uv/) (даёт команду `uvx`). Креды можно задать двумя способами - выбирайте, что удобнее.

**Вариант 1 - переменные окружения** (безопаснее: секрет не попадает в файл). В `.mcp.json` значения подставляются из окружения через `${...}`.

bash / zsh (Linux, macOS) - чтобы переменные сохранялись между сессиями, добавьте строки в `~/.bashrc` или `~/.zshrc`:

```bash
export NEXTCLOUD_HOST=https://home.softmus.ru
export NEXTCLOUD_USERNAME=your_username
export NEXTCLOUD_PASSWORD=your_app_password
```

Windows (PowerShell) - `setx` пишет переменные в профиль пользователя; они появятся в **новых** окнах терминала:

```powershell
setx NEXTCLOUD_HOST "https://home.softmus.ru"
setx NEXTCLOUD_USERNAME "your_username"
setx NEXTCLOUD_PASSWORD "your_app_password"
```

**Вариант 2 - вписать значения прямо в `.mcp.json`** вместо `${...}`: проще, файл неверсионный и в репозиторий не попадёт, но пароль хранится в нём открытым текстом.

Если Nextcloud не нужен, удалите его блок из `.mcp.json.template` (и `.mcp.json`). Полный список инструментов и режим Docker - в [README сервера](https://github.com/cbcoutinho/nextcloud-mcp-server).

### Скиллы

Готовые навыки в формате `SKILL.md` - открытый кросс-агентный стандарт, его понимают и Claude Code, и Codex. В Claude Code лежат в `.claude/skills/` и подхватываются автоматически; после миграции на Codex (см. выше) - в `.agents/skills/`:

| Скилл                 | Назначение                                                                                              |
|-----------------------|---------------------------------------------------------------------------------------------------------|
| **obsidian-markdown** | Obsidian-разметка: коллауты, эмбеды, свойства/frontmatter (ссылки - markdown-абсолютные, не wikilinks). |
| **obsidian-bases**    | Создание и правка `.base` - табличных/карточных представлений.                                          |
| **json-canvas**       | Создание и правка `.canvas` - канвасов, mind map, схем.                                                 |
| **obsidian-cli**      | Уникальное из CLI: граф бэклинков, задачи, шаблоны, dev-слой (CRUD - файлами, поиск - через MCP).       |
| **defuddle**          | Чистый Markdown из веб-страницы для ресёрча (готовую заметку агент кладёт в `inbox/`).                  |

### Frontmatter и даты - не редактируются вручную

Плагин **Frontmatter Date Manager** сам ведёт `created` и `updated` (формат `yyyy-MM-dd'T'HH:mm:ss`), пока Obsidian открыт. Исключения, которые плагин не трогает: `README.md`, `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md` и всё в `.claude/`, `.agents/`, `.codex/`, `templates/`, `tmp/`.

### Личные инструкции для агента

То, что не должно уезжать в общий репозиторий, держите в `CLAUDE.local.md` в корне (он в `.gitignore`) - Claude грузит его автоматически рядом с `CLAUDE.md`; скилл `migrate-to-codex` переносит его содержимое в `AGENTS.md` вместе с `CLAUDE.md`.
