# Obsidian Second Brain — стартовый шаблон

Преднастроенное хранилище [Obsidian](https://obsidian.md) для ведения личной базы знаний (*second brain*) с поддержкой работы AI-агента (Claude Code). Вместо "голого" Obsidian вы сразу получаете рабочую структуру папок, набор плагинов, единые конвенции ссылок и дат, синхронизацию через Git и готовые инструкции для AI.

Шаблон управляется **в две руки**: вы — через интерфейс Obsidian, AI-агент — через файловую систему.

> [!note] Контент — на русском
> Заметки в базе ведутся на русском языке. Папки `inbox/`, `knowledge/`, `meetings/`, `projects/`, `archive/` в шаблоне пустые (только `.gitkeep`) — это каркас, который вы наполняете своими заметками.

---

## TL;DR — что внутри

- **Структура папок** под методику second brain: входящие, база знаний, встречи, проекты, архив.
- **11 community-плагинов** + донастроенные core-плагины (Bases, Canvas, Templates).
- **Единые конвенции:** Markdown-ссылки с абсолютным путём (не wikilinks), вложения в `_files/`, автоведение дат во frontmatter.
- **Git-синхронизация** через плагин (pull при старте + авто-commit/pull/push каждые 15 минут).
- **Готовность к AI:** инструкции `CLAUDE.md` и скиллы в `.claude/skills/`.

## Установка

### Шаг 1. Установите Obsidian

Скачайте и установите Obsidian для своей ОС с [obsidian.md/download](https://obsidian.md/download).

### Шаг 2. Получите шаблон (без git-истории)

Шаблон лежит в `git.softmus.ru/Softmus/Obsidian-bootstrap`. Вам нужна **рабочая копия без истории** репозитория-шаблона — дальше вы ведёте её в **своём личном** репозитории.

**Вариант А — скачать архивом (проще):**

1. Откройте репозиторий шаблона в веб-интерфейсе.
2. Скачайте архив (`Download ZIP` / вкладка `Releases`).
3. Распакуйте в папку будущего хранилища, например `~/second-brain`.

**Вариант Б — через git с удалением истории:**

```bash
# 1. Поверхностный клон (только последний коммит)
git clone --depth=1 https://git.softmus.ru/Softmus/Obsidian-bootstrap.git second-brain
cd second-brain

# 2. Отвязать от шаблона — удалить его историю
rm -rf .git          # Windows (PowerShell): Remove-Item -Recurse -Force .git

# 3. Начать свою историю и подключить ЛИЧНЫЙ репозиторий
git init
git branch -M main
git remote add origin <URL-вашего-личного-репозитория>
git add .
git commit -m "init: second brain from bootstrap"
git push -u origin main
```

> [!important] Подключайте свой репозиторий, а не шаблонный
> `origin` должен указывать на **ваш личный** репозиторий, иначе вы рискуете запушить личные заметки в общий шаблон. Личный репозиторий заранее создайте пустым в `git.softmus.ru` (или там, где вам удобно).

### Шаг 3. Откройте папку как хранилище

В Obsidian: **Open folder as vault** → выберите папку из шага 2.

При первом открытии Obsidian спросит про сторонние плагины — нажмите **Trust author and enable plugins** (выход из Restricted Mode). Плагины уже перечислены в шаблоне и включатся автоматически.

После первого запуска проверьте обновления и убедитесь, что плагины включены: **Settings → Community plugins** → **Check for updates** (при наличии — **Update all**), затем пробегитесь по списку и включите те, что остались выключенными.

### Шаг 4. Проверьте синхронизацию

Плагин **Git** настроен на автоматическую синхронизацию: `pull` при старте (`autoPullOnBoot`), плюс авто-commit-and-sync и авто-`pull` каждые 15 минут (коммит происходит через 15 минут после последней правки). Меняйте заметки, ничего не нажимая, — изменения сами уедут в ваш репозиторий. Синхронизировать немедленно: палитра команд → `Git: Commit-and-sync`.

> [!warning] Возможны merge-конфликты
> При расхождении истории (например, правки с двух устройств или чужой push) плагин выдаст merge-конфликт и **не разрешит его сам** — это придётся сделать вручную через git-клиент. Если работаете с нескольких устройств, открывайте Obsidian по очереди и дожидайтесь синхронизации.

### Шаг 5 (опционально). Настройте AI-агента

См. раздел [Работа с AI-агентом](<#работа-с-ai-агентом>) — там установка CLI и обзор скиллов.

## Как пользоваться (метод second brain)

База — это не свалка файлов, а растущий граф связанных заметок. Рабочий цикл:

1. **Захват.** Всё новое и недодуманное — в `inbox/`. Не раскладывайте преждевременно.
2. **Разбор inbox.** Периодически разбирайте входящие: дробите на атомарные заметки, добавляйте ссылки на связанное, переносите "вечнозелёное" в `knowledge/`, встречи — в `meetings/`, проектное — в `projects/`.
3. **Связывайте.** Стройте граф Markdown-ссылками между заметками — связи ценнее тегов и папок.
4. **Архивируйте, не удаляйте.** Потерявшее актуальность переносите в `archive/`.
5. **Ресёрч.** Изучая тему, собирайте источники и сохраняйте готовую заметку в `inbox/`.

### Структура папок

| Папка        | Назначение                                                             |
|--------------|------------------------------------------------------------------------|
| `inbox/`     | Входящие: быстрый захват, неразобранные черновики, результаты ресёрча. |
| `knowledge/` | Постоянная база знаний: атомарные "вечнозелёные" заметки.              |
| `meetings/`  | Заметки встреч.                                                        |
| `projects/`  | Проектные заметки и материалы.                                         |
| `archive/`   | Устаревшее — не удаляем, а архивируем.                                 |
| `_files/`    | Вложения (картинки, PDF). Скрыта из навигатора.                        |
| `templates/` | Шаблоны заметок.                                                       |

### Конвенции, которые легко нарушить по привычке

- **Ссылки — Markdown с абсолютным путём от корня, не wikilinks.** Пишите `[Текст](Папка/Заметка.md)` и `![](_files/файл.png)`, а не `[[Заметка]]`. Плагины сами нормализуют ссылки и чинят их при переименовании/перемещении.
- **Новые заметки → `inbox/`** (создаются там автоматически).
- **Вложения → `_files/`** (складываются автоматически, папка скрыта).
- **Даты во frontmatter не трогайте руками.** Поля `created`, `updated`, `updated_count` ведёт плагин, пока Obsidian открыт.

Полные канонические правила — в [`CLAUDE.md`](</CLAUDE.md>).

## Работа с AI-агентом

Шаблон рассчитан на то, что часть рутины ведёт AI-агент (Claude Code): захват, структурирование, связывание и поиск по базе. Инструкции для агента и канонические конвенции хранилища лежат в [`CLAUDE.md`](</CLAUDE.md>) — Claude подхватывает его автоматически из корня.

### Установка Claude Code

**Claude Code** — официальный CLI Anthropic. Установите по инструкции [docs.claude.com/claude-code](https://docs.claude.com/en/docs/claude-code). Он автоматически подхватывает `CLAUDE.md` и скиллы из `.claude/skills/`.

Запускайте CLI из корня хранилища — тогда агент видит инструкции и работает по конвенциям базы.

### Как агент пишет в базу

Агент читает и пишет `.md` напрямую через файловые инструменты — проще, быстрее, работает и при закрытом Obsidian. Запущенный Obsidian мгновенно подхватывает изменения на диске, поэтому агент сверяется с актуальным состоянием файла перед правкой.

### Скиллы (`.claude/skills/`)

Готовые навыки, которые Claude Code подхватывает автоматически:

| Скилл                 | Назначение                                                                             |
|-----------------------|----------------------------------------------------------------------------------------|
| **obsidian-markdown** | Obsidian-разметка: коллауты, эмбеды, свойства/frontmatter.                             |
| **obsidian-bases**    | Создание и правка `.base` — табличных/карточных представлений.                         |
| **json-canvas**       | Создание и правка `.canvas` — канвасов, mind map, схем.                                |
| **obsidian-cli**      | Чтение / создание / поиск заметок, задачи и свойства из CLI.                           |
| **defuddle**          | Чистый Markdown из веб-страницы для ресёрча (готовую заметку агент кладёт в `inbox/`). |

### Frontmatter и даты — не редактируются вручную

Плагин **Frontmatter Date Manager** сам ведёт `created`, `updated`, `updated_count` (формат `yyyy-MM-dd'T'HH:mm:ss`), пока Obsidian открыт. Исключения, которые плагин не трогает: `README.md`, `CLAUDE.md` и всё в `.claude/`, `templates/`, `tmp/`.

### Личные инструкции для агента

То, что не должно уезжать в общий репозиторий, держите в `CLAUDE.local.md` в корне (он в `.gitignore`) — Claude грузит его автоматически рядом с `CLAUDE.md`.

## Git и синхронизация

- Синхронизация — через плагин **Git**: `pull` при старте (`autoPullOnBoot`) + авто-commit-and-sync и авто-`pull` каждые 15 минут (коммит — через 15 минут после последней правки, режим debounce).
- Правки сохраняются и уезжают сами; синхронизировать немедленно — палитра команд → `Git: Commit-and-sync`.
- При расхождении истории (правки с двух устройств, чужой push) возможны merge-конфликты — плагин их не разрешает, нужно вмешаться вручную.
- Перед началом работы помните, что Obsidian мог сделать pull — сверяйтесь с актуальным состоянием.
- В `.gitignore` исключены `workspace.json` (состояние UI), `.trash/`, `.DS_Store`, `.idea/` и `CLAUDE.local.md`.
